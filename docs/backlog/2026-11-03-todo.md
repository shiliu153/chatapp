#### [x] A-1【P0·功能】Web 端 IM 静默断连:心跳 + `onClose` + 退避重连 + 重连补拉

- **证据**:[review §N-1 与附录 A](../reviews/2026-11-03-fullstack-review.md)(`ws_server.cpp:231-247` 75s 空闲踢出、`transport.ts:2-6` 无 `onClose`、`client.ts:60` 只挂 `onFrame`、`stores/chat.ts` 无心跳定时器)
- **现象**:网页端进聊天页后静置 75 秒,服务端关连接,前端仍显示 `ready`,对方新消息**静默丢失**;App 有 25s 心跳,不受影响。
- **要做的事**:
  1. `SelfTransport` 加 `onClose(fn)`,`BrowserWebSocketTransport` 挂 `ws.onclose`/`ws.onerror`;
  2. `SelfImClient` 加 25s 业务 `ping`(与 App 对齐),把 `onClose` 映射为独立事件 `disconnected`(**不要**与 `kickedOffline` 合并);

  4. 保持既有约束:`multiAccount`(同端多标签互踢)**不得**自动重连(见 `stores/chat.ts:131-143`,曾 10 秒打 27 次 `user_sig` 被限流)。
- **验收**:按 review 附录 A 复现(静置 80s 后由 B 发消息)→ 页面应自动重连并补拉到该消息;新增单测:假 transport 注入 `onClose` → 断言 `reconnecting` → 断言退避后 `connect` → 断言触发补拉。
- **依赖**:无。**预估**:半天。
- **开新对话提示词**:`读 docs/backlog/2026-11-03-todo.md 的 A-1 条,以及 docs/reviews/2026-11-03-fullstack-review.md 的 §N-1 与附录 A,按条目执行;先写失败测试再改实现;完成后按发布流程开 PR。`
