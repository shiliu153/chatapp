# 运维探针

本分册含 2 个接口:存活探针 `/health` 与就绪探针 `/readyz`。

**这两个接口供负载均衡、监控与部署脚本使用,客户端(App)不需要调用。** 它们无需鉴权,为便于脚本读取,保持与业务接口一致的 JSON 风格。

---

### 7.1 存活探针

> `GET` `/api/v1/health` · 无需鉴权 · 无额外限流

**接口描述**

进程存活检查:只要服务能响应即返回 `ok`。不检查任何外部依赖。

**响应示例**

```json
{ "status": "ok" }
```

**状态码**

| HTTP | 含义 | 处理建议 |
|------|------|----------|
| 200 | 服务存活 | — |
| 无响应/超时 | 进程已挂或不可达 | 触发重启或告警 |

---

### 7.2 就绪探针

> `GET` `/api/v1/readyz` · 无需鉴权 · 无额外限流

**接口描述**

就绪检查:对 MySQL 与 Redis 各做一次真实探测(DB 执行 `SELECT 1`;Redis 写入并读回)。**全部通过**返回 200;任一依赖异常返回 503,并在 `checks` 里标出是哪一项。

**响应参数**

| 参数名称 | 类型 | 描述 |
|----------|------|------|
| status | String | `ok`(全部正常)/ `unavailable`(任一依赖异常) |
| checks | Object | 各依赖的探测结果:`db`、`redis`,取值 `ok` / `error` |

**响应示例**

全部正常(HTTP 200):

```json
{ "status": "ok", "checks": { "db": "ok", "redis": "ok" } }
```

Redis 异常(HTTP 503):

```json
{ "status": "unavailable", "checks": { "db": "ok", "redis": "error" } }
```

**状态码**

| HTTP | 含义 | 处理建议 |
|------|------|----------|
| 200 | 所有依赖就绪 | 可接收流量 |
| 503 | 至少一项依赖不可用 | 从负载均衡摘除;查看服务日志定位(日志会打印失败探针名) |
