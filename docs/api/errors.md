# 错误码

所有失败响应的结构见 [conventions.md §统一响应结构](conventions.md#统一响应结构):`{"code", "message", "request_id"}`。

## HTTP 状态码语义

| HTTP | 含义 | 常见触发 |
|---|---|---|
| 400 | 参数或业务校验失败 | 参数缺失/格式错误;不能划自己、不能举报自己、不能拉黑自己;未满 18 岁;照片数量超限 |
| 401 | 未认证或令牌失效 | 未带 `Authorization`;access 过期;refresh 无效/已拉黑;**被其他设备顶号(带 `40101`)** |
| 403 | 权限不足 | 账号被重封禁(`banned_heavy`);轻封禁(`banned_light`)用户提交滑卡;访问需管理员权限的资源 |
| 404 | 资源不存在 | 目标用户/动态/照片不存在;**被双向拉黑的人一律按「不存在」处理**(防探测) |
| 405 | 方法不允许 | 对只支持 GET 的接口发 POST 等 |
| 429 | 触发限流 | 超过 [conventions.md §限流总览](conventions.md#限流总览) 中的额度;或短信重发间隔/锁定(带 `42901` / `42902`) |
| 500 | 服务端异常 | 未预期错误。请把响应里的 `request_id` 提供给服务端排查 |
| 503 | 依赖服务不可用 | 短信任务入队失败(`50301`);`/readyz` 探针异常 |

## 业务码总表

带专属业务码的错误如下(其余错误 `code` 等于 HTTP 状态码):

| 业务码 | HTTP | 含义(message) | 处理建议 |
|---|---|---|---|
| 40101 | 401 | 账号已在其他设备登录,请重新登录 | 本机账号已被顶下,清空本地凭证并回到登录页;若为本人操作,重新登录即可把对方顶下 |
| 40001 | 400 | 验证码已过期,请重新获取 | 重新调用 `POST /api/v1/auth/sms/send` 获取新验证码 |
| 40002 | 400 | 验证码错误 | 提示用户核对后重试;注意连续错误 5 次会锁定 15 分钟(`42902`) |
| 42901 | 429 | 发送太频繁,请稍后再试 预计 N 秒后可用。(N 为距可重发的剩余秒数) | 按响应头 `Retry-After`(秒)等待后重试;同一手机号 60 秒内只能发一次 |
| 42902 | 429 | 错误次数过多,请稍后再试 | 按响应头 `Retry-After`(默认 900 秒 = 15 分钟)等待后重试 |
| 50301 | 503 | 短信服务暂时不可用,请稍后重试 | 稍后整体重试;此错误下服务端已回滚发送占位,可立即重试 |

## 封禁行为

平台对违规账号有两级封禁,客户端表现如下:

| 封禁级别 | 影响范围 | 返回 |
|---|---|---|
| `banned_light`(轻封禁) | 仅禁止滑卡 | 提交滑卡返回 `403`(账号已被限制,暂时无法滑卡);聊天、广场、资料等功能不受影响 |
| `banned_heavy`(重封禁) | 全域禁止 | 除白名单外的**所有**接口返回 `403`;白名单:`GET /api/v1/users/me`、`GET /api/v1/users/tags` |

补充说明:

- 被封禁账号的资料对外不可见(他人访问其资料返回 `404`)
- 封禁信息会出现在 `GET /api/v1/users/me` 响应的 `status` 字段(`banned_light` / `banned_heavy`)
- 封禁与解封由运营后台操作,会通过系统消息通知本人
