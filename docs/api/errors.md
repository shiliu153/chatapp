# 错误码

所有失败响应的结构见 [conventions.md §统一响应结构](conventions.md#统一响应结构):`{"code", "message", "request_id"}`。

## HTTP 状态码语义

| HTTP | 含义 | 常见触发 |
|---|---|---|
| 400 | 参数或业务校验失败 | 参数缺失/格式错误;不能划自己、不能举报自己、不能拉黑自己;未满 18 岁;照片数量超限 |
| 401 | 未认证或令牌失效 | 未带 `Authorization`;access 过期;refresh 无效/已拉黑;**被其他设备顶号(带 `40101`)** |
| 403 | 权限不足 | 账号被重封禁(`banned_heavy`);轻封禁(`banned_light`)用户提交滑卡;访问需管理员权限的资源;**号码不在准入名单(带 `40301`)** |
| 404 | 资源不存在 | 目标用户/动态/照片不存在;**被双向拉黑的人一律按「不存在」处理**(防探测) |
| 405 | 方法不允许 | 对只支持 GET 的接口发 POST 等 |
| 413 | 请求体过大 | 账号媒体存储配额已满(带 `41301`);照片/聊天图/语音/广场图上传均可能触发 |
| 429 | 触发限流 | 超过 [conventions.md §限流总览](conventions.md#限流总览) 中的额度;或短信重发间隔/锁定(带 `42901` / `42902`);或每日喜欢额度用完(带 `42904`) |
| 500 | 服务端异常 | 未预期错误。请把响应里的 `request_id` 提供给服务端排查 |
| 503 | 依赖服务不可用 | 短信任务入队失败(`50301`);语音转码缺 ffmpeg(`50302`);`/readyz` 探针异常 |

## 专属业务码在哪查

**本页不维护「业务码总表」**(2026-11-14 治理第 6 节删除)。原因:那张表是
[`chatapp/config/error_codes.py`](../../chatapp/config/error_codes.py) 的手写副本,已经漂移过 ——
文件里有 13 个码,总表只列了 11 个,`40301` 与 `50302` 长期只在分册里出现。
**同一事实两处手写必然分叉**,所以码的 owner 只留一处:

| 想知道 | 去哪 |
|---|---|
| 有哪些码、码是什么(机器可读) | [`chatapp/config/error_codes.py`](../../chatapp/config/error_codes.py)(前 3 位 = HTTP 状态码,后 2 位 = 序号) |
| 某个码的**含义与处理建议** | 该接口所在**分册的「错误码」小节**,例如 `40301` → [auth.md](auth.md)、`50302` → [im.md](im.md)、`41301` → [users.md](users.md) |

怎么查一个码:① 按上表定位 HTTP 状态码语义;② 带专属业务码的错误,含义与处理建议写在对应分册;
③ 机械保证:**每个业务码至少在一份分册里出现**,由 `python scripts/docs_index.py --check` 判定
(新增一个码却没有任何分册提到它 → CI 红)。

## 封禁行为

平台对违规账号有两级封禁,客户端表现如下:

| 封禁级别 | 影响范围 | 返回 |
|---|---|---|
| `banned_light`(轻封禁) | 仅禁止滑卡 | 提交滑卡返回 `403`(账号已被限制,暂时无法滑卡);聊天、广场、资料等功能不受影响 |
| `banned_heavy`(重封禁) | 全域禁止 | 除白名单外的**所有**接口返回 `403`;白名单:`GET /api/v1/users/me`、`GET /api/v1/users/tags` |

补充说明:

- 被封禁账号的资料对外不可见(他人访问其资料返回 `404`)
- 封禁信息会出现在 `GET /api/v1/users/me` 响应的 `status` 字段(`banned_light` / `banned_heavy`)
- 封禁与解封由运营后台操作,会通过系统消息通知本人
