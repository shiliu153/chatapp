# 公共说明

所有 `/api/v1` 接口共用的约定。读具体接口前建议先读本页。

## Base URL

| 环境 | Base URL |
|---|---|
| 对外(域名待备案) | `http://<域名>/api/v1` |
| 当前测试环境 | `http://<SERVER_IP>/api/v1` |
| 本机开发(浏览器 / curl) | `http://127.0.0.1:8000/api/v1` |
| 本机开发(Android 模拟器) | `http://10.0.2.2:8000/api/v1` |

HTTPS 待域名备案后启用。本文档所有示例中的 `http://<域名>/api/v1` 均可替换为对应环境的 Base URL。

## 请求约定

| 项 | 约定 |
|---|---|
| 请求方法 | `GET` 查询 / `POST` 创建 / `PATCH` 局部更新 / `DELETE` 删除 |
| 请求体 | JSON 接口用 `Content-Type: application/json`;文件上传用 `multipart/form-data` |
| 请求 ID | 请求头可带 `X-Request-Id`;不带则服务端生成,响应头 `X-Request-Id` 回填 |
| 字符编码 | UTF-8 |

## 鉴权

除 [auth.md](auth.md) 的登录/刷新接口与 [health.md](health.md) 的探针外,所有接口都需要鉴权:

```http
Authorization: Bearer <access>
```

- **令牌对**:`access` 有效期 30 分钟,`refresh` 有效期 30 天
- **刷新即轮换**:每次调用 `POST /api/v1/auth/token/refresh` 都会签发新的 `access` 与 `refresh`,旧的 `refresh` 立即进入黑名单
- **单设备登录**:同一账号同时只允许一台设备在线。在第二台设备登录会顶掉第一台;被顶设备的后续请求返回 `401` + `code: 40101`,客户端应清空本地凭证并回到登录页
- 令牌缺失/格式错误/过期:返回 `401`,`code` 为 `401`,具体原因见 `message`

## 统一响应结构

**成功**:HTTP 2xx + 资源 JSON(数组、对象或分页对象,见各接口)。

**失败**:一律为下列结构(所有非 2xx 响应都是这个形状):

```json
{
  "code": 42901,
  "message": "发送太频繁,请稍后再试",
  "request_id": "b0d0a2f1c3e44f7d"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | Integer | 业务码。规则:前 3 位与 HTTP 状态码一致,后 2 位为业务序号(如 `42901` = HTTP 429 + 序号 01)。无专属业务码时等于 HTTP 状态码本身(如 `400`、`404`) |
| message | String | 面向用户的中文提示,可直接展示 |
| request_id | String | 本次请求的追踪 ID,排查问题时提供给服务端 |

客户端做分支判断**以 `code` 为准**,不要匹配 `message` 文案。完整错误码清单见 [errors.md](errors.md)。

> 例外:少数接口里**接口内直接校验**的失败(目前是「在线状态参数错误」与「照片超过 6 张」两处)只返回 `code` + `message`,**不含 `request_id`**。客户端解析时请把该字段当作可选。

## 分页约定

所有列表接口统一使用 `limit` / `offset` 分页:

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| limit | Integer | 否 | 每页条数,默认 20,上限 100(超出按 100 计) |
| offset | Integer | 否 | 偏移量,默认 0 |

**响应结构**

```json
{
  "count": 137,
  "next": "http://<域名>/api/v1/posts?limit=20&offset=20",
  "previous": null,
  "results": []
}
```

`next` / `previous` 为完整 URL,没有下一页/上一页时为 `null`。

## 时间格式

所有时间均为 ISO 8601 字符串,客户端按 ISO 8601 解析后转本地时区展示即可。实际存在两种渲染:

| 渲染 | 示例 | 出现位置 |
|---|---|---|
| 带时区偏移(Asia/Shanghai) | `2026-09-20T20:35:12+08:00` | 在线状态 `last_active_at` |
| UTC 带 `Z`(含微秒) | `2026-09-19T04:38:32.767758Z` | 分页列表里的时间字段,如配对列表的 `matched_at` |

两种都表示绝对时刻,以各接口的响应示例为准。

## 限流总览

超限返回 `429`,并带 `Retry-After` 响应头(秒数)。

| 场景 | 额度 | 维度 |
|---|---|---|
| 发送短信验证码 | 20 次/小时 | 按客户端 IP |
| 校验短信验证码 | 60 次/小时 | 按客户端 IP |
| 提交滑卡动作 | 300 次/小时 | 按用户 |
| 举报用户 | 20 次/天 | 按用户 |
| 发布动态 | 20 次/天 | 按用户 |
| 发表评论 | 60 次/天 | 按用户 |
| 举报动态 | 20 次/天 | 按用户 |
| 查询在线状态 | 600 次/小时 | 按用户 |

以上为生产口径。此外**同一手机号 60 秒内只能发送一次验证码**、**验证码连续错误 5 次锁定 15 分钟**,这两条是业务规则,与 IP 限流相互独立。

**关于 429 响应的文案差异**(调用方需知):

- 业务规则拦截(60 秒重发间隔、验证码锁定)→ 中文文案 + 专属业务码 `42901` / `42902`
- 上表限额触发(框架限流器)→ `message` 为框架英文默认文案(形如 `Request was throttled. Expected available in 42 seconds.`),`code` 为 `429`

两种情形都带 `Retry-After`,客户端按 `code`(429 或 42901/42902)统一处理即可。

## 测试环境专用行为

以下行为**仅在测试环境生效**,正式上线后取消:

| 行为 | 说明 |
|---|---|
| 验证码固定为 `123456` | 不会真实发送短信,直接用它即可登录(上线接入短信商后按真实短信填写) |
| 上传照片自动过审 | 测试环境上传即通过审核,不需要等待人工审核 |
