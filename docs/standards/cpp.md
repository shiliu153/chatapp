# C++ 注释规范

适用于 `imserver/` 下全部 C++20 代码:`src/` 的 52 个文件,加 `tests/` 里 15 个 gtest 用例文件(`.h` 与 `.cpp` 同一套)。

**和 [python.md](python.md) 的关系**:两份分册回答同一个问题——新人只看注释能不能上手;字段口径已经对齐
(2026-11-14 起 Python 侧也是五小节:参数说明 / 返回参数 / 使用示例 / 备注信息),差别只在**载体**:
Python 用模块 docstring + 缩进小节,`imserver/` 用 SeekFree 风格的**文件头块 + 五字段注释块**。
C++ 侧不改造成 docstring 形态,理由见 §1。

## 检查入口与基线

| 手段 | 入口 | 现状 |
|---|---|---|
| 机械门禁 | 无 | 未立项,理由见 §8 |
| 人工 | 改 `imserver/` 任一 `.cpp` / `.h` 前对照 §4 的边界表 | 强制 |

**基线**(2026-11-14 按 `imserver/` 实测;数字都可以用下面的命令复算,不靠记忆):

| 项 | 实测 |
|---|---|
| 带文件头的文件 | 67 = `src/` 52 + `tests/` 15;头部 22 行(唯一例外见 §2.3) |
| 函数注释块 | 637 = `src/` 529 + `tests/` 108 |
| 每个块的字段 | 5 个,637 块全覆盖(函数简介 / 参数说明 / 返回参数 / 使用示例 / 备注信息) |

| 落在函数体内部的块 | 0 |

## 1. 为什么 C++ 侧保留文件头与 `//---` 块

| | Python(`chatapp/`) | C++(`imserver/`) |
|---|---|---|
| 文件头 | 模块 docstring:一句话职责 + 按需小节 | 22 行定长块:许可证、版本、修改记录都在里面 |
| 函数注释 | 五小节 docstring:`参数说明:` / `返回参数:` / `使用示例:` / `备注信息:`(首行即简介) | 5 字段块:`函数简介` / `参数说明` / `返回参数` / `使用示例` / `备注信息` |
| 分节手段 | 空行 + 缩进 4 空格的正文 | 上下两条 117 显示列的分隔线 |
| 作者与时间 | 不写(git blame 即事实) | 文件头有 `修改记录`,只追加 |
| 规范从哪来 | 本项目自定(取腾讯规范之意,换 Python 的形) | SeekFree 风格模板,已在 67 个文件落地 |

**字段含义是同一套**,两边可以对照着读;不一样的只有排版:Python 靠空行与缩进分节,C++ 靠分隔线,
因为 `.cpp` 里没有 docstring 这种语法容器,注释必须自己把边界画出来。

两边也不是双标:Python 那套是**我们自己定的形**,C++ 这套是**已经落地的形**。把 67 个文件的注释改成
docstring 形态,唯一收益是「两边长得一模一样」,代价是全部注释差量重写一遍、三端契约相关的踩坑结论
在迁移里重述一遍 —— 收益填不上成本。所以 C++ 规范跟着现状走,只在**新代码怎么加**这件事上
把口径收紧(§4)。

### 2.2 字段

| 字段 | 写什么 | 约束 |
|---|---|---|
| 首两行(职责 / Copyright) | 项目定位 + 版权行 | 全库一致,不按文件改写 |
| `额外注明` | 许可证指路 + 版权声明要求 | 这两行是**许可依据**,不许删、不许改写 |
| `文件名称` | 该文件在 `imserver/` 内的相对路径,如 `src/net/ws_server.h`、`tests/like_test.cpp` | 不写 `imserver/` 前缀,不写本机绝对路径 |
| `项目名称` | `chat_app / imserver` | 固定 |
| `公司名称` | `个人项目（shiliu153）` | 固定(项目定位见 `CLAUDE.md`「项目概况」) |
| `版本信息` | `查看 app/pubspec.yaml 内 version 字段 版本说明` | **不在这里写版本号**:唯一事实来源是 `app/pubspec.yaml`,三处一致性由 `python scripts/sync_version.py --check` 校验 |
| `开发环境` | `CMake 3.22 + g++ (C++20) Linux x86_64` | 固定 |
| `适用平台` | `Linux x86_64 服务端` | 固定 |
| `仓库地址` | `https://github.com/shiliu153/chatapp` | 与 `scripts/lib/repo.py` 的 `DEFAULT_REPO` 同源,别各写各的 |
| `修改记录` | 日期 / 作者 / 备注 三列 | **只追加新行**,不改旧行 |

许可证是 **MIT**:法律文本在仓库根 `LICENSE`(`Copyright (c) 2026 shiliu153`),文件头里那句
「许可申明英文版见仓库根目录 LICENSE 文件」就是指向它。

### 2.3 规则

- **位置**:文件第 1 行开始、顶格,在 `#pragma once`(头文件)或第一条 `#include`(实现文件)之前。
- **行数**:基准 22 行。唯一允许的扩展是在 `额外注明` 段内补**一行**文件级说明 ——
  现库只有 `src/net/frames.h` 一处(该文件是三端唯一的 WS 帧契约源),因此它是 23 行;
  其余字段顺序与行数不变。
- **`.h` 与 `.cpp` 各一份**。同一个模块的两个文件头部只有 `文件名称` 一行不同。
- 改动时**只改 `修改记录`**:加一行 `日期 / 作者 / 备注`,历史行保留。

## 3. 函数注释块

### 3.1 形状与尺寸

```cpp
//-------------------------------------------------------------------------------------------------------------------
// 函数简介     ...
// 参数说明     ...
// 返回参数     ...
// 使用示例     ...
// 备注信息     ...
//-------------------------------------------------------------------------------------------------------------------
```

- **分隔线**:`//` + 115 个 `-`,整行 **117 显示列**;每个块**上下各一条**(共 2 条),不借用、不省略。
  相邻两块之间是「上块的收尾线 + 下块的开头线」两条独立分隔线,不会合并成一条。
- **字段区**:固定 5 行,顺序固定;`备注信息` 允许续行,续行以 `//` + 14 个半角空格 起,与值列对齐。
- **位置**:块紧贴函数签名上方,中间不空行;块与被注释函数之间不插入其它声明。
- **只加注释**:注释改动不碰签名、不碰函数体。2026-11-14 那轮 67 个文件的 diff 是 `+6605 / -0`。

对齐用的是**显示列**(一个汉字算 2 列),不是字节数:

| 位置 | 写法 | 效果 |
|---|---|---|
| 字段名 | `// ` + 4 个汉字字段名 + 5 个半角空格 | 值统一起于第 **16** 显示列 |
| `参数说明` 的参数名 | 参数名 + 空格补齐到 17 显示列(现库 762 处) | 说明起于第 **33** 显示列;一个参数一行 |
| `返回参数` 的类型名 | 类型 + 空格补齐到 9 显示列(现库 516 处) | 说明起于第 **25** 显示列;类型超过 9 列(如 `std::optional<uint64_t>`)时补 1 个空格即可,右溢不算错 |

### 3.2 五个字段怎么写

| 字段 | 判据 | 例(取自 `src/util/uuid.h`) |
|---|---|---|
| `函数简介` | 动宾短句,一句话说清「做什么」,8~20 字,不以「本函数」开头;测试文件写「用例 验证…」 | `生成 32 字符随机十六进制串` |
| `参数说明` | 每个参数一行:名字 + 补齐 + 一句话;**写清默认值与单位**;无参数写 `无` | `max_per_ip       单 IP 并发连接上限 默认 20` |
| `返回参数` | 类型 + 补齐 + 一句话;`void` 统一写 `void             无返回值`;`optional` / 空指针要写清「空值代表什么」 | `std::optional<uint64_t>     合法返回 uid 否则 nullopt` |
| `使用示例` | **一行真能编译的调用**;构造写 `Class obj(参数)`,运算符写 `a = b` / `a + b` 形态;测试写 `ctest -R 套件.用例` | `const std::string id = random_uuid();` |
| `备注信息` | 只写「为什么 / 坑 / 约束」:配对调用、所有权、异常规格、并发假设、跨栈约定;**不重复签名已经说清的东西** | `返回 true 后必须配对调用 release 否则名额泄漏` |

三条补充:

- **参数说明不写类型**(类型在签名里),但**默认值必须写**——调用方最常问的是「不传会怎样」。
- **备注信息不写会失效的编号引用**:`见 spec §5` 这类不写(与 [python.md](python.md) §5 的行内注释同口径)。
  行内注释里既有的批次标记(`L9:`、`M-8` 之类)不动,新写的注释不再新增这类标记。
- **与既有的 `///` 说明并存**:`imserver/` 里还有大量 `///`,多用于**类型 / 字段 / 跨端约定**这类
  函数块讲不了的事,不要删。分工是:`///` 讲「为什么这样设计」,块讲「怎么调用、参数什么意思」。

## 4. 边界表:哪些加块、哪些不加

判据只有一条:**有函数实体(签名 + 实现)的地方加块;类型、指令、表达式不加。**

| 场景 | 加块 | 现库证据(2026-11-14) |
|---|---|---|
| 命名空间级函数,含 `.cpp` 匿名 namespace 里的本地 helper、测试文件里的辅助函数 | **加** | `src/net/ws_server.cpp` 匿名 namespace 的 `now_ms()` / `parse_uid()` / `is_sticker_id()`;`tests/guard_test.cpp` 里给测试造地址的 `ip()` |
| 构造函数 / 析构函数 / 运算符重载 | **加**;使用示例写真实形态(`Class obj(...)`、`a = b`) | `src/store/mysql_pool.h` 的 `Lease(MysqlPool&, MYSQL*)`、`~Lease()`、`operator=(Lease&&)`;`src/store/stmt.h` 的 `MysqlError(int, const std::string&)` |
| 类内 inline 定义(函数体写在类里) | **加,块放定义处** | `src/store/mysql_pool.h` 的 `MYSQL* get() const { return conn_; }`、`src/util/media_sign.h` 的 `bool enabled() const { return !secret_.empty(); }` |
| 模板函数 | **加**(与普通函数同形) | 现库 0 个模板函数;将来加了照此执行 |
| `main()` | **加** | `src/main.cpp`(备注写清「非回环监听必须显式 `IM_ALLOW_PUBLIC_BIND=1`」) |
| gtest `TEST(套件, 用例)` | **加**,简介写「用例 验证…」,使用示例写 `ctest -R 套件.用例` | `tests/` 的 15 个用例文件共 108 个块 = 107 个 `TEST` + 1 个辅助函数 |
| 纯数据结构 / `struct` 字段 | **不加**,用 `///` 或行内注释 | `src/store/models.h` 只有文件头、0 个函数块 |
| lambda、函数体内的局部对象 | **不加** | `src/main.cpp` 的 `signals.async_wait([...](...){...})` 与 `threads.emplace_back([&io] { io.run(); })` |
| 宏 | **不加** | `imserver/src` 与 `imserver/tests` 下 0 个 `#define`;将来有,只写文件头 |
| `= delete` | **不加**(表明接口不存在,没有实现可讲) | 10 处:`src/store/stmt.h`、`src/store/mysql_pool.h`、`src/store/redis_client.h`、`src/service/push_notifier.h` |
| `= default` | **按「定义处」处理**:定义写在 `.cpp` 且承载函数语义时加块,备注里点明 `= default` | `src/store/stmt.cpp` 的 `Stmt::~Stmt() = default;` 有块;对应 `src/store/stmt.h` 的 `~Stmt();` 声明也有块 |

一条硬事实:637 个块**没有一个**落在函数体内部。块分隔线的缩进只有两种 —— 顶格 1260 条、
类体缩进 2 空格 14 条(`src/util/media_sign.h`),缩进 ≥4 空格的为 0。函数体里出现的 `//`
都是行内注释(解释「为什么」),不套块。

## 5. 声明处与定义处各一份

头文件声明 + `.cpp` 定义 → **两处各一块**,不是「写一处就够」。这与 `src/net/ws_server.h` /
`src/net/ws_server.cpp` 的既有做法一致。

- 声明处的块面向**调用方**:参数含义、返回语义、典型调用;
- 定义处的块面向**维护者**:可以讲实现选择(为什么在这里加锁、为什么先重试再丢弃连接);
- 两块**不要求逐字相同**,按各自视角取舍。`src/util/uuid.h` 与 `src/util/uuid.cpp` 的 `random_uuid()`:
  定义处的备注多一句实现细节(「每次调用用 `std::random_device` 重新播种 `mt19937_64` 取两个 64 位值
  拼 16 字节」),声明处不写这段;其余四个字段两处一致。
- 全部写在头文件里的 inline 函数只有一处定义,自然只有一块。

同形三例:`src/util/uuid.{h,cpp}`、`src/net/ws_server.{h,cpp}`、`src/store/mysql_pool.{h,cpp}`。

## 6. 缩进与文件内一致性

- 现库两种写法:多数文件块**顶格**(1260 条分隔线);`src/util/media_sign.h` 的类成员块整体
  **缩进 2 空格**(14 条,分隔线整行 119 列,`-` 的个数不变)。
- 规则:**跟随所在文件的既有写法**,同一个文件里不许混用;新建文件从顶格开始。
- 块与上文之间:现库约六成(390 / 637)块前空一行,其余紧跟 `public:` / `private:` 或上一段代码。
  规则:与上一段代码之间空一行;**紧跟访问控制标签或类体首行时不空**;同一文件内保持一致。
- 文件末尾保持一个换行(仓库统一),不要在块后留多余空行。

## 7. 改了代码之后跑什么

```bash
# imserver 一条栈(3 道门禁:unit、integration、http e2e)
scripts/verify.sh imserver

# 只跑单元测试(容器内 cmake 构建 + ctest -L unit)
cd imserver
docker build -f Dockerfile.dev -t imserver-dev .
docker run --rm -v "$PWD:/src" imserver-dev bash /src/scripts/test.sh

# 单条用例(套件.用例;先跑上一条,让挂载卷里的 /src/build 就绪)
docker run --rm -v "$PWD:/src" imserver-dev \
  bash -c 'ctest --test-dir /src/build -R LikeTest.WrapsKeywordWithPercent --output-on-failure'
```

- **纯注释增量也要跑**:块紧贴函数签名,任何一处 `/*` 与 `//` 拼错都会让编译失败,而这类错误
  只在编译时暴露,review 看不出来。
- 只改 `docs/` 时跑 `scripts/verify.sh contract` 就够,不必起容器。

## 8. 门禁现状(为什么还没有检查脚本)

**现在没有机械门禁**,这是刻意留的、也是暂时的:

- 这套注释是「块」不是 docstring,没有 AST 级入口。能机检的三件事(分隔线宽度、5 字段齐全、
  函数块覆盖率)都需要能识别函数定义的解析器(clang-query / tree-sitter),正则判不准 ——
  `.h` 里的声明、`.cpp` 里的定义、lambda、`= delete` 在文本上长得都像函数。
- 误报的硬门禁会降低规范权威性。[python.md](python.md) §7 已经定过这个口径:`参数说明:` 小节
  只报告、不拦截。
- 现在靠:review 按 §4 的边界表看 + 本文件开头的复算命令核基线。
- 若要立项:脚本放 `scripts/`(`docs/` 下只放文档,见 [writing.md](writing.md) §6 与 `docs_lint`
  的 structure 规则),命令注册进 `scripts/gates.toml` 的 `contract` 组,本地与 CI 用同一个
  执行器 `scripts/run_gates.py`。归属上,代码在 `imserver` 栈、脚本在 `flow` 栈,
  **一次改动只碰一条栈**。

## 9. 正反例

### 正例

`src/util/uuid.h` 的 `random_uuid()`(声明处):简介说「做什么」,参数写「无」,返回写清了
「32 字符小写十六进制」而不是「返回字符串」,备注交代了**它不是 RFC 4122 UUID** ——
这条是删掉注释后人必然踩的坑。见 §3.3。

### 反例

```cpp
//-------------------------------------------------------------------------------------------------------------------
// 函数简介     自增
// 参数说明     i                要自增的数
// 返回参数     int              返回值
// 使用示例     i = inc(i);
// 备注信息     无
//-------------------------------------------------------------------------------------------------------------------
int inc(int i) { return i + 1; }
```

字段齐全、宽度也对,但这块等于噪音:简介与代码重复,备注写「无」。判据是
**删掉整块,后人重新踩坑的概率会不会上升** —— 不会,就该补上真正看不出来的东西
(边界行为、溢出、调用约束),补不出来就不该有这个块。

```cpp
//-------------------------------------------------------------------------------------------------------------------
// 函数简介     处理
// 参数说明     无
// 返回参数     void             无返回值
// 使用示例     handle();
// 备注信息     无
//-------------------------------------------------------------------------------------------------------------------
void WsSession::handle_send(const nlohmann::json& frame) { ... }
```

`handle_send` 明明有参数、返回 void、还要讲帧格式与 42201 的拒绝路径,却写成「无 / 无返回值 / 无」——
字段齐了但内容错,比缺字段更难发现。**五字段是形状,内容要按 §3.2 填**。
